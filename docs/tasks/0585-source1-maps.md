## Goal and ownership
Import BSP world geometry, displacements, brush models and static props. Resolve embedded materials and reuse model data for repeated props.

Owned paths or surfaces: src/scene/source1_map*, dedicated BSP tests. Coordinate registration and shared interface changes through the mounting round.

## Acceptance and verification
A map with a displacement and two differently transformed instances retains geometry, material assignments and both transforms after reopening. Derive independent tests from these criteria. Use scratch projects, run the Windows and Linux suites and relevant import/editor stress checks, and record exact commands and results. Cite repository revisions, primary format references and fixture provenance for consequential claims.

The map reader must carry the classic material and texture identities supplied by task 0584 into the combined map import, including assets of static props. Task 0583 maps those identities to stable project destinations. Task 0588 verifies preservation of material edits and assignments across reimport, resource reordering and cache relocation.

## Implementation and evidence

- The combined map import carries the material and texture identities recorded by the classic reader, including identities from each model used by static props. All missing-prop markers share one material with its own map-relative identity. Joined reimport and cache-relocation verification is tracked in task 0588.
- The reader records native world geometry, placed brush models and full-resolution displacement geometry. BSP surface texture vectors supply per-corner UVs. Map-packed dependencies take precedence over other mounted content. Static props sharing a model path share its imported meshes. A prop whose geometry cannot load keeps its placement as a magenta marker, with its virtual path in the import diagnostics.
- Brush entity placement accepts ASCII case-insensitive keys and fills omitted trailing origin or angle components with zero. The parser rejects malformed, nonfinite or extra components. [Valve entity lookup](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/src/utils/common/bsplib.cpp#L2940-L2945), [Valve vector conversion](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/src/game/shared/util_shared.cpp#L844-L878).
- Initial implementation is against Blendity `f83be355`. The dedicated synthetic BSP in `tests/test_source1_map.cpp` is built in memory from authored data and contains no game assets. It uses signed surfedges, an oriented odd plane, a partly raised power-2 displacement with a hole, and a brush model placed twice. It checks the mesh, UVs, materials and transforms before and after moving the source mount and reopening the native scene.
- Valve's SDK layout and behavior are documented in [BSP records](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/src/public/bspfile.h), [face emission](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/src/utils/vbsp/writebsp.cpp#L391), [brush submodel local coordinates](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/src/utils/vbsp/map.cpp#L1471), [displacement grid and tessellation](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/src/public/builddisp.cpp#L842), [serialized static props](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/src/utils/vbsp/staticprop.cpp#L498) and [QAngle orientation](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/src/mathlib/mathlib_base.cpp#L1115).
- Two additional files were inspected at the binary record level. [SFM Workshop item 791304326](https://steamcommunity.com/sharedfiles/filedetails/?id=791304326), item revision timestamp `1477982231`, contains a VBSP 21 map with 47 version-9 static props, 104 stored pakfile entries and two collinear brush face loops. Map SHA-256 `f86d0596fe486e684fd12447800603d4ed8476aef181a206d6418eb9c3fa706a`. Valve's [Half-Life 2 Deathmatch Lockdown BSP](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/game/mod_hl2mp/maps/dm_lockdown.bsp) is VBSP 19 with 40 displacements, version-5 static props and six retraced zero-area loops. Map SHA-256 `93e4c7367b99cf35bae30467acc10c31c8bea48ac5199e80f5e73cc490da3523`. The files remain in scratch storage. Runtime results are recorded separately.
- The compatibility scope is little-endian VBSP 19–21 with supported lump layouts and an uncompressed geometry stream. Nondefault static prop skins use the model reader's default skin and produce a named diagnostic. Lightmaps, engine lighting and gameplay behavior are outside this geometry and material import.
- The independent Windows red run of the two brush topology regressions at test revision `716f1232` reported 1,403 checks and two failures. Both cases lost the material slot with the omitted floor. The repair splits retraced surfedge walks into closed cycles and uses the BSP's triangle list or strip whenever present, preserving the compiled vertex order, authored UV projection and material. Zero-vertex primitive records index the original face winding. Explicit-vertex records use absolute indices into the primitive vertex lump within the record's span. [Valve T-junction primitives](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/src/utils/vbsp/faces.cpp#L616), [subdivided-face primitive vertices](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/src/utils/vbsp/faces.cpp#L1394), [surfedge and strip order](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/src/utils/common/bsplib.cpp#L3013).
- A scratch binary-record audit of the Warehouse map accounts for all 18 previously dropped nonzero-area windings, totalling 89.467432 m². Face 3 retains a 28-corner loop covering 60.231102 m² when its two retraced spurs are removed. The audit found no visible Warehouse winding with nonzero area and no surviving cycle or primitive triangle. The joined runtime retest remains separate.

### Stable resource identity follow-up

With the identity-aware `ImportResult`, the map reader carries child material and decoded-texture identities into the combined result. The associations use the canonical virtual identifiers supplied by the classic material reader. The shared missing-prop marker uses the canonical map path and its marker role. No lookup key from the process is stored in the native scene.

All three offline map comparisons passed. The identity-aware Warehouse run reports 13 texture entries and matches all 47 placements. Independent re-review approved the identity propagation.
