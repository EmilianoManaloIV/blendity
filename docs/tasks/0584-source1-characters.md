## Goal and ownership
Read MDL, VVD and VTX companions, default skin and bodygroup, VMT materials and VTF textures into native meshes, skins and materials.

Owned paths or surfaces: src/scene/source1_model* and source1_material*, dedicated model tests. Coordinate registration and shared interface changes through the mounting round.

## Acceptance and verification
A posed joint moves the expected weighted vertices. An asymmetric mesh renders with correct winding, scale, UVs and alpha. A missing geometry companion reports its virtual path. Derive independent tests from these criteria. Use scratch projects, run the Windows and Linux suites and relevant import/editor stress checks, and record exact commands and results. Cite repository revisions, primary format references and fixture provenance for consequential claims.

For a classic SFM humanoid with ValveBiped names, verify bind and manual posing and editor rig Auto IK on both arms and legs. On a fresh unskinned copy of the imported humanoid verify marker-based humanoid auto-rigging. Check weighted deformation, undo and save/reopen. Preserve props and nonhumanoids. Record fixture provenance and distinguish generated inputs from verified title assets. Report shared rig-system faults to the verification round.

Verify that each model surface binds its expected editable native material, that base colour, UVs, cutout and each supported texture channel survive conversion, and that missing or unsupported resources identify their virtual paths. In joined verification, check project-owned texture files and matching renders after a cold reopen with mounts and temporary import cache removed, then verify explicit reimport preserves material edits.

Classic material and texture identities must survive encounter-order changes, source-byte edits and a changed staging root. Same-basename resources from different virtual paths must remain distinct even with identical texture bytes. Different conversions of one VTF must remain distinct. A missing VMT fallback must keep the identity of the material it represents, including when a relative MDL reference later resolves in a different search directory or directly under materials. Verify two consecutive reimports preserve edits while those two resolution routes supply the material. Two logical surface bindings must remain independently editable when they resolve to the same VMT. Invalid references need distinct bounded fallbacks, and a model without a material table must identify its default material.

## Implemented scope

- The reader accepts desktop MDL 48 and 49 with VVD 4 and VTX 7. It reconstructs VVD vertex order from the fixup table and uses LOD 0, skin family 0 and bodygroup variant 0. A loaded companion must match the MDL checksum. The VTX path supports the ordinary and expanded v49 packed headers. Source positions use `(-y, z, x) * 0.0254` and Source rotations use the corresponding basis conjugation. VTX index order is clockwise in the unreflected Source frame, so the reflection makes the unchanged order agree with Blendity's geometric normals. V is converted from top-origin to bottom-origin.
- The inverse of `poseToBone` defines each joint's bind matrix. Confirmed ValveBiped and TF-style limb chains use a changed local joint basis for native +Y bone tips. Applying the same basis to a limb joint's bind and current world matrices preserves `pose * inverse(bind)` and the imported joint origins. Recognized static props skip the skeleton and weights.
- VertexLitGeneric, LightmappedGeneric and UnlitGeneric produce editable native materials. The importer reads direct VMT fields and Patch includes with insert/replace; it takes the largest mip of the first VTF frame and stages PNGs for Blendity's ordinary asset copy. Common integer formats, DXT1/DXT1 one-bit alpha, DXT3, DXT5 and ATI compressed data are handled. Source-specific shaders, layered maps, animation, flexes and alternative model variants are outside this reader's conversion. The material report identifies unsupported shader and texture references, including EyeRefract.
- The reader searches relative material candidates in declared directory order, then checks the direct path if needed. It attaches import-only identities based on canonical VMT paths for a single candidate and on canonical MDL path plus source reference for bindings with multiple candidates. VTF identities pair canonical paths with conversion roles. Default materials use the MDL path and default role. Distinct invalid VMT references receive bounded fallback identities. Staging paths include separate resource and byte digests to keep distinct virtual inputs from sharing a lookup path.
