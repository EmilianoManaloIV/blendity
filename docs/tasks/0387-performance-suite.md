# Task 0387: The performance suite and the responsiveness budget (round 411)

- **Status:** built
- **Requirements:** Q-04, Q-06 (new: responsiveness), C-04 (the suite runs on a scratch project)
- **Decisions:** ADR 0105 (the budget; ADR 0056 amended)
- **Model:** main session (Fable)
- **PR:** on main

## Asked
"Do a full performance suite on the program. Rendering, Baking, or doing intensive operations should not halt the
program. Implement efficiencies as needed. [...] Use VRChat world and avatar unity packages to measure performance
(use Side Rail and Shinano) as very real projects. [...] Make sure to go over every tool and operation in Blendity to
check if there is room for optimization." The first of Pass 16's rounds: the measuring instruments and the budget,
before any fix.

## Built
- **ADR 0105** states the budget (no frame over 50 ms while a job runs, one frame of at most 100 ms for an operation
  that can't be split, every worker in the tray, long frames visible) and adds **Q-06** to `docs/requirements.md`;
  ADR 0056 is amended: the six frame-bound asserts in `test_gpu.cpp` / `test_livelink.cpp` print instead of checking.
- **The frame tells the truth:** the deferred callbacks (an import's busy step, dialogs) are timed inside the frame
  (`FrameProfile::ms_deferred`, `frame_ms_`, the frame history); `perf status` prints the last frame with its parts, the
  worst of 240, the jobs and the views' device; `perf mark <name>` is a script's stopwatch (the time, the frames and
  the longest frame since the last mark); `viewport status` prints where the views draw and the badge's reason.
- **The honest CPU badge:** a view the card refused (a see-through toon material, a Volume, a Principled extra, textures
  past the card's buffers, HDR with see-through) shows the badge with the reason in its tooltip; before, only an
  absent card did and the refusal hid in the Profiler (`Editor::cpu_badge_reason`, reading the Scene view's own slot:
  another view's refusal is the Profiler's to list). The time a user sits in a native file dialog (a deferred callback)
  is taken off the frame (`picker_ms_`): not the frame's work.
- **`benchscene worldlike` / `worldlikequick`:** the committed Unity-world stand-in (600 parts from 40 meshes, 180
  Contribute GI, 70 lights with ranges, 4 reflection probes, 300 or 64 textures written once into the scratch project,
  30 materials with 6 see-through toon, 2 glass, a mirror and a cloth with sheen, fog, the camera's Bloom / Vignette /
  Color Grading).
- **Stress sections** (`stress/stress_main.cpp`): `responsiveness` (every heavy operation headless with the views open:
  F12 raster and path traced, Render Animation, a camera sequence, Generate Lighting, mesh maps, Bake Textures, a surface,
  Boolean, Decimate, Subdivide, DynaMesh, Quad Remesh, skin bind, Join / Separate, Apply Modifiers, undo of 10k objects,
  Edit Mode at 500k, save / open of big scenes, import / export of six formats, the stand-in's build, bake and render;
  the longest frame, the mean, the total, the frames, the tray's label, OVER / ok), `operations` (the inventory sweep:
  every console verb with one real invocation from `stress/sweep_commands.inc`, generated by `tools/sweep_commands.py`
  from the tests, every keymap action and every window, each in a fresh headless editor on one of three saved scenes -
  the starter scene with its teapot selected, the stand-in, 10k cubes - so no verb's state (`threads 2`, a theme, a
  window, a dialog) reaches the next row; the slowest 40 and every one over 50 ms in the table, all in the CSV with
  commas quoted), `world_like` (the stand-in's Scene and Game view frames on the CPU and the card with the hashing /
  gathering / GPU-path parts and the card's refusals). The three run only when named (`--only`) or through
  `tools/perf_suite.py`: minutes each.
- **`tools/perf_suite.py`:** runs the sections, `bench_ui.py` and `bench_world.py`, compares every row with
  `stress/results/baseline.md`, prints regressions and OVER rows, `--save-baseline`, `--write` into PERFORMANCE.md's
  Pass 16 block, `--check` for CI; the regression rule reads time columns only (ms, s, frames, bytes, MB - a rate such as
  Mrays/s growing is not a regression). **`tools/bench_world.py`:** a real project's pipeline step by step through
  `perf wait` (frames stepped until no job, render or bake runs: the `--cmd` lines run with no frame between them) and
  `perf mark` (import, open, Unity's numbers and lightmaps, a bake, F12, the exports) and the views' frames through
  `--windowed-check`; the user's SideRail and Shinano projects are measured locally and never committed.
- The lesson "Where the Time Goes"; `tests_round411`.

## Acceptance criteria
1. A deferred callback of 40 ms shows in the frame's time and the history; `perf mark` and `perf status` report as
   documented; `viewport status` prints the device and the badge's reason.
2. `benchscene worldlikequick` builds the counts above; the sweep's lists are complete (every verb, sorted and unique).
3. `blendity_stress --only responsiveness|operations|world_like` run and write their tables; `tools/perf_suite.py`
   compares them with the baseline and writes PERFORMANCE.md's Pass 16 block; `tools/sweep_commands.py --check` passes.
4. Both suites, the audits.
