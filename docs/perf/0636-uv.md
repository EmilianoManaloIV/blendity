## Linux experiment design

The Linux CPU editor and packing probes use GCC 15.2 release objects. The baseline is `d7503d4e`. Its source, external code, tests, version and build scripts match the release object donor `a3d6cc8c18d92a3982a7fa9dc4b24fb0089abeb1`. Each pair changes only the production translation unit under investigation. Scratch projects and CPU rendering isolate the editor fixtures.

[The pane probe](../../tools/bench/0636-uv-pane.cpp) reports command dispatch and time through the next completed frame in milliseconds. Each case starts a new editor. Fixture setup precedes the clock. Mixed winding, seam and selection mutations occur between dispatch and the frame. The stretch fixture varies the 3D face areas and checks the resulting range. Each block has two samples per binary. The first block runs baseline then candidate and the second reverses that order. The acceptance threshold is a reduction of at least 10% and 5 ms in **both** blocks. A mandatory control is materially slower if the increase exceeds both 10% and 0.5 ms in both blocks.

[The packing probe](../../tools/bench/0626-uv.cpp) runs `SIDE 9 pack` for sides 24, 96 and 192, using connected and fragmented grids. Each block has nine measured calls per binary and workload. The second block reverses binary order. The constrained profile uses CPU 0 and `BLENDITY_THREADS=1`. The ordinary profile uses the available process affinity. The acceptance threshold is a reduction of at least 7% and 0.05 ms in both blocks. An increase above both 5% and 0.05 ms in both blocks is material. Separate allocation-counting executables use the same production objects. Allocation probes use `SIDE 0 pack`.

To reproduce the pane comparison on x86-64 Linux, use a separate checkout and release build for each revision. Copy the same `0636-uv-pane.cpp` into each scratch area. From each checkout root, link it in place of the application entry point against that checkout's objects. The commands below use the dependency-free GCC configuration from this run.

```bash
BLENDITY_NO_LIBS=1 ./build.sh release app
bank=build/obj_release_linux
read -r -a flags < "$bank/flags.txt"
flags=("${flags[@]:2}")
objects=()
for obj in "$bank"/{src_,extern_}*.o; do
  [[ ${obj##*/} == src_app_main.cpp.o ]] || objects+=("$obj")
done
c++ "${flags[@]}" -Isrc "$probe_source" "${objects[@]}" \
  -lX11 -ldl -static-libstdc++ -static-libgcc -o "$scratch/uv-pane"
```

Set `probe_source` to the absolute path of the probe and `scratch` to an existing scratch directory. For each sample, use fresh project, trash, preferences and cache directories, set the viewport, GI and denoise devices to CPU, and run `"$scratch/uv-pane" all "$scratch/run-prefix"` with a unique prefix. Compare the resulting `.rgba` files with `cmp` and the UV signatures in the `ROW` records. The [operator build instructions](0626-uv.md#reproducing-the-operator-measurements) describe the separate packing probe.

The cache lives for one pane draw and uses the original rasterizer. For eligible footprints the staging image is bounded at 8 MiB. Four two-byte coverage arrays can add up to 8 MiB in total, and the existing fixed-point comparison can use another 4 MiB. These buffers are allocated on demand.
