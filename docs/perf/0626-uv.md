# Complex UV actions (task 0626)

## Workloads and checks

The baseline is `90136ffc072f5b9b1c8be2be4ab2e2413b97fdd4`. Its editor, UV solver, tests and build sources match the verified Pass 35 integration at `6ed52dc02b8e0659d72b583661500ac425d7f428`. The Windows full editor used for the application checks had SHA-256 `6b0f57419ebf92fb8ad0c8702579cfff00418dcc17ea2617d0486a5ac24af9d4e`. All operations used scratch files and preferences.

**Editor selection and transforms.** Five synchronous subdivisions of the default cube gave 6,144 quads. Smart UV produced six charts. Each action started again from this state. For selection checks, the full editor translated its selected corners by (+0.25, −0.125); a separate reader resolved position and UV indices in the exported Wavefront faces. It found chart membership by crossing edges only when position and UV matched at both ends. For transforms it applied the requested formula around face 17's original bounding-box center and compared every exported corner to the prediction. The largest absolute coordinate error was 0.00000145, including decimal export precision. Positions and face indices agreed in every export.

Reproduce the starting mesh with `jobs async off`, `select Cube`, `subdivide 5`, `uv smart`. Select with `uvsel mode face` and `uvsel face 17`; the toolbar uses the same `uv_select` and `uv_transform` paths as `uvsel` and `uvxf` (`src/editor/uv_editor.cpp`). The exact exported-value oracle and its results are in the Hub evidence directory `0626/editor/sweep.py` and `results.json`. These are correctness observations, without a latency claim.

**Full application mapping commands.** Thirteen actions ran on fresh copies of the 6,144-face cube. Each command exported the selected mesh. An independent reader resolved each face corner's texture index, checked finite UVs and compared every face index and vertex position to the control. The exported results for Cube, Cylinder, Sphere, View, Reset and Unwrap differed from the starting Smart UV map at all 24,576 corners. Average and Pack ran after Cylinder, and their outputs also differed from the Smart UV reference at every corner. That comparison alone cannot separate the effects of those two commands from Cylinder. The fragmented operator fixture verifies equal density and correct packing independently. Smart UV after Cylinder returned to the reference exactly. Part Unwrap on faces 17–20 changed 16 corners and preserved the other 24,560. Exact edge selection marked and cleared four seams. On face 17 of the smooth subdivided mesh the sharp-edge command reported zero new seams, and its unwrap variant changed four corners. The separate cube/cylinder sharp-edge tests provide positive seam-creation controls. See `0626/editor/operators.py`, `operator-results.json` and the `0626-edit2` queue receipt. This run also checked the editor's whole-object UV Report after every action.
**Toolbar and redraw.** On the same 6,144-face cube, the mouse switched to Vertex and Island modes and exercised All, None, Invert, ±90°, both flips, Fit, Center, numeric Move, Scale and Rotate. For all 14 state-changing clicks the resulting canvas or mode toolbar pixel region matched the corresponding command reference and differed from its initial state. Clicking the already-active Face control matched its reference without a state change. These 15 completed pairs are in `0626/editor/ui-results.json`.

Clicking Reset then triggered a separate baseline limit. The 1600×900 CPU-viewport process logged that UV Reset had completed and did not finish its headless capture within the 60-second process limit. The earlier editor export had verified the reset coordinates without displaying the UV pane. Reset maps every quad to the full UV square; the pane fills the visible faces individually (`src/editor/uv_editor.cpp`). Repeated overdraw is a hypothesis. The timeout bounds the whole capture and does not isolate frame time. Later toolbar clicks in that batch have no result.
## Operator benchmark

`tools/bench/0626-uv.cpp` drives production UV routines on a bent, rippled grid and on separate 2×2 pieces. Each fixture has a partial face mask and existing external seams. The 96×96 grid has 9,216 faces (9,024 selected). Part Unwrap uses at most 24×24 faces to bound chart search. The 192×192 projection workload has 36,864 faces (36,480 selected). The connected and fragmented fixtures exercise different island counts while keeping total face count fixed.

Each action starts from the same mesh. Stock-allocator binaries time the warmed production operator. Separately linked probes count C++ allocation requests and requested bytes; their output signatures must match the stock binaries. Input preparation and result validation run outside the measured interval. Repeated outputs include a signature of corner UVs, seams and result data. The checks cover mask exclusion, stable topology and chart membership, atlas bounds, nonempty and nonoverlapping packed chart boxes on these fixtures, and equalized texel density. The vertex-list seam rows use a prepared vertex selection, while the editor seam commands exercise exact selected edges. The operator Report uses a face mask and the editor Report uses the whole mesh. View uses a synthetic perspective matrix in the operator harness and the current camera in the editor. Stretch takes the whole mesh. Allocation counts refer to a mesh that already has UVs. Creating a missing UV layer requires additional storage. Ordinary and single-logical-CPU runs use native GCC 15.2 Linux release objects. Constrained results describe CPU affinity and job count only.

The largest measured latency was dependency-free LSCM on the connected chart: 950.762 ms with ordinary CPU affinity (0–31) and 193.590 ms on CPU 0. The same face count split into small charts took 3.658 and 6.239 ms. Island traversal alone took 1.357 and 0.512 ms on ordinary affinity for connected and fragmented meshes respectively. The two profiles also change worker count and scheduling, so the comparison cannot isolate dispatch overhead. Solver tuning remains open.

Cylinder and Sphere Projection now track the minimum and maximum U coordinate as each selected face is projected. The previous routine allocated a vector for every selected face and scanned it twice. ### Editor command timing

A separate headless Linux editor probe linked the release editor and the exact baseline or candidate UV object. Each sample used a freshly subdivided cube with Reset UVs. It timed the complete `Editor::command` dispatch for Cylinder or Sphere, advanced a frame, checked that the undo stack grew by one, and hashed all resulting UVs and seams. Frame rendering and the deferred undo snapshot are outside the timed interval. All 80 matched sample pairs produced the same signatures. On a 1,536-face cube, the probe also opened Mesh > UV and clicked fourteen named menu items. All fourteen returned the same UV/seam signature as their direct commands, and thirteen changed that signature. Seams from Sharp added zero seams on its smooth selected fixture. The Mark/Clear rows started with exact selected edges and checked a real state change. The Pack and Average menu rows also changed the signature on their prepared input.
### Packing experiment

An additional candidate skipped collecting hull points with rotation disabled and moved the point vector into the hull routine with rotation enabled. Axis-aligned packing was 6.82–13.25% faster across the tested sizes, profiles and layouts. Default rotated packing ranged from 7.14% faster to 2.28% slower. On the constrained 9,216-face fragmented case both block medians slowed (2.60% and 0.57%). The production change therefore keeps the existing packing implementation. Packed coordinates, chart labels, masks, and atlas validation all agreed.

### Reproducing the operator measurements

From the repository root in a C++17 Linux environment, build the dependency-free measurement program in scratch. The production UV and mesh code is linked directly:

```sh
g++ -std=c++17 -O2 -DNDEBUG -pthread -ffunction-sections -fdata-sections -Isrc \
  tools/bench/0626-uv.cpp src/scene/uv.cpp src/scene/uv_abf.cpp \
  src/scene/uv_parts.cpp src/scene/mesh.cpp src/scene/mesh_tools3.cpp \
  src/core/core.cpp src/core/jobs.cpp -Wl,--gc-sections -o /tmp/uv0626
/tmp/uv0626 96 3
/tmp/uv0626 192 9 cylinder
/tmp/uv0626 192 9 sphere
```

Use the same harness and compiler flags with each production revision. For a constrained comparison set `BLENDITY_THREADS=1` and restrict both processes to the same available logical CPU. Alternate baseline/candidate, then candidate/baseline. Compare the signature and quality fields in every paired CSV row before comparing operator medians. For allocation counts, compile a separate executable with `-DBL_UV_BENCH_ALLOCATIONS` and run it with sample count zero. This checks results and records C++ allocation requests without taking a timing sample. Timing windows on the shared development machine are assigned by the Hub.

**Production UV stress on Windows.** The full release stress binary exercised both LSCM solvers. On a 64×64 grid both produced one island. On a 50,176-face sphere Smart UV produced eight charts. On the 12-material version, Part Unwrap produced twelve charts with mean and worst distortion 1.03. On the 2,048-face teapot it selected eleven charts from 99 attempts, including two ABF++ solves, with mean 1.13 and worst 1.17. The stress report is `0626/uv-stress.Q1TCza/report/latest.md`.
