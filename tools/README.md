# tools/

What is here, and what is local-only.

| Tool | What it does | Run |
|---|---|---|
| `perf_suite.py` | The performance suite in one command (round 411, ADR 0105): the stress sections (`responsiveness`, `operations`, `world_like` and the older rows), `bench_ui.py`, `bench_world.py` for the real projects given; every row compared with `stress/results/baseline.md` (a cell grown over 20 %, an OVER row); `--save-baseline` (with `--sections` only those sections are replaced, round 468), `--write docs/PERFORMANCE.md` (the pass16-table block), `--check` (fails on a regression or a row newly OVER; a row the baseline already has OVER is listed as "still over", round 468); `posing` is in the default sections since round 468 | `py tools/perf_suite.py [--quick] [--ui] [--world "<project>|<scene.unity>"] [--write docs/PERFORMANCE.md]` on a quiet machine |
| `bench_world.py` | A real Unity project's pipeline step by step (import, open, `unity modelids`, `unity lightmaps`, a bake, F12, the exports) through `perf wait` and `perf mark`, and its Scene / Game view frames on the CPU and the card through `--windowed-check`; report.md / report.json; nothing of the project is committed. Round 468: `--posing` plays real drags on the avatar (`perf drag`: its root, FK bones, Puppet handles, IK targets and poles, G, a scrub), plays a clip and enters Play, headless and in a real window, with each row's press / first-move / mean / longest / release frames and the frame's parts; `--avatar-package` / `--avatar-prefab` put an avatar into the opened scene; `--settings` adds the settings matrix, `--avatar-at` / `--camera` / `--prop` stand the avatar, set the Scene view and name a prop to move; these run on a copy of the project under `--out` (the project given is never written; the report says so); `--frames N`, `--no-pipeline`, `--self-test` | `py tools/bench_world.py --exe dist/windows/Blendity.exe --project <dir> --scene <scene.unity>` (or `--prefab`, or `--package` into a scratch project); `... --prefab <avatar.prefab> --posing --no-pipeline`; `... --scene <world.unity> --avatar-package <avatar.unitypackage> --avatar-prefab <avatar.prefab> --posing --settings --no-pipeline` |
| `sweep_commands.py` | The inventory sweep's table (`stress/sweep_commands.inc`): one real invocation per console verb taken from the unit tests, the verbs not run headless listed with the reason; `--check` fails when the committed table is out of date | `py tools/sweep_commands.py [--check]` |
| `make_books.py` | The two books (task 0386, ADR 0104): `--bib` writes `docs/book/refs.bib` and `docs/book/generated/*.tex` from the lessons' `> ` and `@ ` lines, `research/FEATURES.md` and `licenses/README.md` (merged with `refs_extra.bib`); `--check` regenerates to a temp folder and fails on drift, an uncited entry or a `\cite` without an entry; `--screenshots <exe>` takes the figures headless from a scratch project; `--pdf [--wsl]` runs latexmk (lualatex + biber) and copies the PDFs to `docs/` | `python tools/make_books.py --bib`, `--check` (CI), `--screenshots dist/windows/Blendity.exe`, `--pdf --wsl` (TeX Live in WSL: `texlive-luatex texlive-latex-extra texlive-pictures texlive-bibtex-extra texlive-fonts-extra fonts-dejavu biber latexmk`) |
| `run_suites.py` | Every test group of every build given as its own process, each with its own `BLENDITY_TEST_DIR` and share of the cores (`BLENDITY_THREADS`), longest first; prints each build's checks, failures and wall time, exits 1 on a failure or crash (task 0371) | `python tools/run_suites.py <blendity_tests> [<another build's>] [--jobs N] [--out DIR] [--filter TEXT] [--timeout S]` from anywhere (each build runs in its own tree) - keep `--out` short; `BLENDITY_TEST_BRIDGE` for one build only |
| `test_coverage_map.py` | Every console command, keymap action and window against the tests that exercise it (task 0177, ADR 0056); `--check` fails on an empty entry; `--widgets` adds the `u.button` labels and Inspector fields with the tests that drive each by label and counts them toward `--check` (task 0251) | `python tools/test_coverage_map.py [--widgets]` from `blendity/` |
| `hci_fitts_audit.py` | Reads the Fitts dump `tests_round271` writes (`fitts-1.0.json`, `fitts-1.5.json`: every window's and tool mode's widget rectangles) and reports the targets under 7 mm at 96 DPI and the index of difficulty from the Scene view's centre, per context and distinct (ADR 0085, task 0251) | `BLENDITY_HCI_DUMP_DIR=<dir> BLENDITY_TEST_FILTER=hci blendity_tests --group editor`, then `python tools/hci_fitts_audit.py <dir>` |
| `hci_klm.py` | Recounts every row of the keystroke-level model table (`docs/hci/klm.md`) from its operators (K 0.2, P 1.1, B 0.1, H 0.4, M 1.35 s) and prints the before and after totals; `--check` fails on a row whose seconds disagree with its operators (ADR 0085, task 0262) | `python tools/hci_klm.py [--check]` from `blendity/` |
| `hci_label_audit.py` | Lists the string literals under `src/editor` that carry a shortcut the keymap does not produce (other tools' keys and mouse gestures skipped); `--check` fails when any remain, for the chain once round 274 moves them to `shortcut_text` (ADR 0085, task 0251) | `python tools/hci_label_audit.py [--check]` from `blendity/` |
| `bench.bat`, `bench_blender.py`, `bench_table.py` | Pass 13's table (task 0178): Blendity's stress rows beside Blender 5.2's, run headless on the same scenes, written into `docs/PERFORMANCE.md`; `BLENDER=path` overrides where Blender is, `BENCH_GPU=name part` which card | `tools\bench.bat [--quick]` on a quiet machine |
| `clean.bat` | Removes `build\`, the stress reports a run wrote (restoring `latest.md`), the inbetweening model's `.venv`; `--all` removes `dist\` and the model's training runs too | `tools\clean.bat` |
| `ptx_compile.cpp` | NVRTC driver that compiles the OptiX kernel to PTX (task 0097); with `--header=` it writes the committed `src/render/optix/optix_kernel_ptx.h` with the sources' hash and the OptiX version (task 0169) | by `optix_ptx_embed.bat` (or `build.bat` with CUDA and no committed header) |
| `optix_ptx_embed.bat` | Writes the committed OptiX PTX header after the kernel changes; needs the CUDA Toolkit (`CUDA_PATH`) and the OptiX SDK (task 0169, ADR 0054) | `tools\optix_ptx_embed.bat` |
| `inbetween/` | The AI inbetweening model's training and export (task 0128): `train.py`, `export_onnx.py`; `.venv/` and `runs/` are local-only (in `.gitignore`) | see `inbetween/README.md` |
| `moonray/` | `clone.sh` and `linux_build.sh`: fetch and build MoonRay on Linux for the bridge (tasks 0112-0114) | by hand, see docs/tasks/0112 |

Local-only, never committed: `inbetween/.venv/`, `inbetween/runs/`, `__pycache__/`, `build/`, `dist/`, the stress
reports beside `stress/results/latest.md`. `tools\clean.bat` removes them.
